# 盖洛普亲密关系复盘

## 开始前

读取 [references/profiles.md](references/profiles.md) 与 [references/relationship-context.md](references/relationship-context.md)。遇到材料中的典型场景时，再读取 [references/scenarios.md](references/scenarios.md)。对话应用要求结构化返回时，读取 [references/output-contract.md](references/output-contract.md)；日、周、月复盘时读取 [references/journal-review-contract.md](references/journal-review-contract.md)。

把才干当作理解行为的假设，不当作诊断、定性或免责理由。区分“材料明确写出”“用户本次明确说出”和“基于才干的推测”。使用“可能、看起来、需要你确认”等措辞标注推测。

把长期关系背景当作需要本次事实校验的工作画像，不当作永远不变的真相。不要因为历史材料已经记录某种模式，就忽略本次实际出现的改善。

## 复盘流程

1. 先检查是否存在人身危险、威胁、强迫控制、自伤或持续羞辱。若存在，优先建议停止现场沟通、确保安全并寻求可信支持；不要用才干解释伤害行为。
2. 判断信息是否足够。至少需要：发生了什么及小娌、小元的实际言行，两人当时各自最想得到什么，以及当前状态。
3. 信息不足时只问 1–3 个最有区分度的问题，不发量表，不要求用户手工打分。优先问：
   - 当时具体发生了什么？小娌和小元分别说了什么、做了什么？
   - 那一刻，小娌和小元各自最希望被看见、认可、配合或保护什么？各自最担心什么？
   - 现在最想达成的是彼此理解、修复关系、作出决定，还是改变一个具体行为？
4. 信息足够后，把事实与解释分开，分别写出双方的内在期待。
5. 判断相关才干处于“适度发挥、过度发挥、受压抑”中的哪一种，并给出本次行为证据。只选真正影响本次互动的 1–3 项才干。
6. 还原互动循环：触发事件 → 才干状态 → 各自解释 → 行为 → 对方受到的影响 → 下一轮升级或断联。
7. 先指出关系里仍然有效的部分，再指出错位。不要裁判输赢，不要求任何一方放弃合理边界。
8. 给出一条现在能说出口的话和一个 24–72 小时内可验证的小行动。需要暂停时，明确何时回来继续谈。

可把原材料的四个策略标签翻译为行为建议，但不要机械套用：双方都适度时用“甜蜜”巩固有效互动；自己适度、对方过度时用“接纳/承担”理解其保护目标并守住边界；自己过度、对方适度时用“感恩”停止证明并接收稳定价值；双方都过度时用“放下/求助”暂停升级并约定恢复时间。

## 沟通原则

- 对小娌：先让努力、成果或情感重要性被看见，再讨论调整；用明确回应和具体参与代替冷处理。避免“你怎么一点……都没有”“这有什么好在意的”。
- 对小元：先降低即时决策压力，说明问题边界和风险，再约定一个明确回应时间；允许分析，但不接受无限拖延或只有解释没有行动。
- 情感支持时，先连接再解决：先确认“你希望我陪你还是一起想办法”，满足连接后再进入分析。
- 共同活动时，把“体验质量”和“彼此交流”拆成两个目标，分别安排时间，避免一方专注细节时另一方把它理解为拒绝连接。
- 家庭责任分歧时，先共同定义“完成”的可观察标准，再分工；认可责任已经履行，再协商质量提升。
- 仪式感分歧时，把庆祝视为表达重视的一种方式，而不是证明爱意的唯一方式；把仪式变成双方可预期的小约定。

## 行为反馈与进步

由分析者分别给小娌与小元本次可观察行为打 1–10 分，不让任何人自己填分。评分只评价本次行为是否有助于连接和解决问题，不评价人格、爱意或关系价值；某一人物证据不足时，该人物分数留空。

- 1–2：明显攻击、威胁、羞辱、强迫或持续惩罚，且没有停止或修复动作。
- 3–4：指责、逼问、扩大化或回避占主导，只有很少自我觉察。
- 5–6：能意识到需求并尝试调整，但仍混有防御、控制、理性压过感受或模糊请求。
- 7–8：能暂停、复述、承认影响、提出具体请求，并为对方保留合理空间。
- 9–10：在高压下仍持续做到双向理解、清晰边界、共同决策和后续兑现。

给出分数必须引用该人物本次具体行为证据，并给出“再提高 1 分”的动作。证据不足时返回空分数，不猜分。比较历史时只与同一人物的相似场景比较，说明是进步、持平、反复还是暂时无法判断；不要把两个人或不同场景的分数机械比较。

同时检查四个维度：是否说清内在期待、是否调节才干、是否回应对方、是否形成合作行动或修复。用“未出现／有尝试／已做到／证据不足”记录证据，维度由系统判断，不要求用户填写。

## 最终答复结构

保持简洁、具体、可说出口：

1. 这次真正卡住的地方
2. 双方内在期待
3. 相关才干及当前状态
4. 小娌与小元各自的行为反馈、分数与历史变化
5. 正确沟通方式：一句示范话术 + 一个小行动
6. 仍不确定且需要验证的一点

完成分析后才生成长期记录。人物数据必须按小娌、小元的固定顺序保存在 `participants` 数组中，共同循环与方案保存在 `interaction` 对象中。只保存精炼的问题摘要、关键词、双方期待、才干状态、沟通方案、行为反馈、分数、进步判断和时间戳；不要把寒暄、重复追问或整段原始聊天写入长期记忆。
