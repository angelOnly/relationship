# 日、周、月 AI 复盘契约

根据传入的周期记录和相似历史，只返回一个 JSON 对象，不使用代码围栏。记录不完整时允许对应人物分数为 `null`，不得补写不存在的事实。

```json
{
  "participants": [
    {
      "participant": {"id": "xiaoli", "name": "小娌"},
      "score": 1,
      "feedback": "对小娌本周期可观察行为的反馈与证据"
    },
    {
      "participant": {"id": "xiaoyuan", "name": "小元"},
      "score": 1,
      "feedback": "对小元本周期可观察行为的反馈与证据"
    }
  ],
  "interaction": {
    "score": 1,
    "summary": "本周期最重要的关系变化，不超过 120 字",
    "what_improved": "与相似历史或上个周期相比的进步；没有基线就明确写暂无基线",
    "risk_pattern": "最需要警惕的一条互动循环",
    "adjustment_goal": "下一个周期只保留一个清晰目标",
    "actions": ["最多三个具体、可验证、带时间或标准的动作"],
    "conversation_example": "一句双方现在可以直接使用的话",
    "confidence": "高|中|低，并说明缺少哪些信息"
  }
}
```

`participants` 必须始终按小娌、小元排序。每个 `score` 都只评价该人物在期待表达、才干调节、回应对方、合作修复上的行为；`interaction.score` 评价本周期互动是否更安全、平等、清楚且有兑现，不是婚姻价值评分。所有分数都是 1–10 的整数或 `null`。

不要根据谁写得更详细就给谁更高分，不要把情绪强烈本身等同于低分。日复盘聚焦一个小调整；周复盘观察重复模式与兑现；月复盘给出趋势和下月唯一重点。完成后只保存上述精炼结论，不保存模型推理过程。
